# ① 选题共创

> 目标：在动笔之前，把「写什么、写给谁、凭什么现在写」定下来。
> 人工确认点：**选题立项必须由人拍板**（脚本只负责记录与去重）。

## 1. 选题从哪里来

选题不是凭空想出来的，本 SOP 只接受四类来源，并对应到素材库：

| 来源 | 说明 | 素材库记录 |
|---|---|---|
| **读者问题** | 后台留言、社群提问、评论区的重复问题 | `materials.md` 条目，标签 `读者问题` |
| **从业经验** | 自己或同事踩过的坑、做过的项目 | 标签 `经验`，附事例与数据 |
| **外部调研** | 新工具、新政策、新事件 | 标签 `调研`，必须附来源链接与时间 |
| **旧文回炉** | 已发文章的延伸、反驳、更新 | 标签 `回炉`，附原文链接 |

> **反例**：因为「今天热点是这个」而写，但自己没有任何一手经验或素材 —— 这类选题最容易写成 AI 泛泛而谈。

## 2. 选题共创的四步

### 2.1 收集（10 分钟）

把过去一周的读者问题、经验、调研记录填进 `topics/materials.md`（格式见第 4 节），不要边收集边判断。

### 2.2 组合（10 分钟）

一个好的选题 = **人群** × **问题** × **你的独特证据**。三者缺一不可：

- 人群：谁关心？（「刚接手公众号的新媒体运营」比「所有人」好）
- 问题：他遇到什么具体困难？（「不知道用什么工具排版」，而不是「想提升效率」）
- 独特证据：你凭什么讲？（一手经验、实测数据、踩坑记录）

### 2.3 写选题卡（10 分钟）

每个候选选题写成一张选题卡（第 5 节模板），至少写 3 个候选，再选 1 个立项。

选题卡必须回答：
1. 这篇读完读者能带走什么（一句话结论）？
2. 我的独特证据是什么？在哪（素材库编号）？
3. 为什么是现在？
4. 同类文章别人已经写过什么？我哪里不同？

### 2.4 立项确认 👤

用脚本登记并立项：

```bash
export PYTHONPATH=tools
python3 -m wechat_sop topics add \
  --title "公众号排版，别再手调样式了" \
  --angle "用一套固定主题 + 一键复制，把排版时间从 30 分钟压缩到 3 分钟" \
  --audience "每周要发 2 篇以上、但不想学 CSS 的公众号运营" \
  --material M2026110301
python3 -m wechat_sop topics list
python3 -m wechat_sop topics use T2026110301 --slug wechat-typography
```

`topics use` 会：
1. 检查选题状态（未立项的才会立项）；
2. 检查必需字段是否齐全（一堆选题卡里漏填「独特证据」是最常见的返工原因）；
3. 生成文章目录骨架（`articles/<日期>-<slug>/`）。

## 3. 选题评审标准（立项前逐条过）

| 检查项 | 通过标准 | 不通过怎么办 |
|---|---|---|
| 单一性 | 能用一句话说清这篇讲什么 | 拆成两篇 |
| 人群 | 能说出具体人群和场景 | 回到收集步骤找读者问题 |
| 证据 | 有至少 1 条一手素材（编号可查） | 先去做实验/调研，暂不立项 |
| 时效 | 能回答「为什么是现在」 | 转为常青内容，优先级降低 |
| 差异化 | 能说出与已有文章的不同 | 换角度或换人群 |
| 体量 | 预估 1500–5000 字 | 超出就拆成系列 |

> 6 项里只要有 1 项不通过，就**不立项**。宁可少选题，不要多废稿。

## 4. 素材库格式（`topics/materials.md`）

```markdown
## M2026110301 读者反复问排版太花时间
- 标签：读者问题 / 运营效率
- 来源：11 月读者群 3 次提问 + 后台留言 2 条
- 要点：多数人卡在「样式每篇不一样」和「图片要手动上传」
- 可引用：需脱敏，不引用原话，概括即可
- 关联选题：T2026110301

## M2026110302 实测 mdnice/doocs 的排版耗时
- 标签：经验 / 调研
- 来源：自测（2026-11-01），同一篇 2500 字文章
- 数据：手调 32 分钟；doocs/md 8 分钟；本仓库脚本 3 分钟（含检查）
- 可引用：可直接引用，注明自测日期与样本
```

## 5. 选题卡格式（`topics/topics.md`）

```markdown
## T2026110301 公众号排版，别再手调样式了
- 状态：draft | planned | writing | published 之一
- 人群：每周发 2 篇以上的公众号运营
- 一句话结论：排版应该是一次配置、长期复用，而不是每篇重做
- 切入角度：从「一篇稿子排版花多久」的实测数据切入，给出固定主题方案
- 独特证据：M2026110301（读者问题）、M2026110302（实测耗时）
- 为什么现在：多数工具已经支持 Markdown 一键排版，但落地流程没写清楚
- 差异化：不只推荐工具，给出一套可执行的流程 + 可复用的检查清单
- 预估字数：2500
- 关联素材：M2026110301, M2026110302
- 文章目录：articles/2026-11-03-wechat-typography/
```

## 6. 常见选题失败模式

| 失败模式 | 症状 | 处理 |
|---|---|---|
| 大而空 | 标题像「XX 的思考」 | 收窄到具体人群与问题 |
| 无证据 | 只有观点没有案例/数据 | 先补素材再立项 |
| 蹭热点 | 讲的事件与自己无一手经验 | 不做，或改为「我从这件事学到什么」 |
| 观点堆砌 | 大纲是 5 个并列观点，没有推进 | 改成「问题 → 原因 → 方案 → 证据」结构 |
| 系列未拆 | 一篇里想讲 3 件事 | 拆成系列，先写第一篇 |

## 7. 前置条件

开始本环节前确认：

- [ ] `topics/materials.md` 与 `topics/topics.md` 已存在（`python3 -m wechat_sop init` 会生成）
- [ ] 本周的读者问题/经验已收集
- [ ] 至少 3 张候选选题卡
- [ ] 👤 已人工拍板立项
