# ③ 成文

> 目标：按大纲把内容写成可发布的稿子，风格稳定、事实可追溯、没有 AI 腔。
> 人工确认点：**事实核查与定稿由人确认**（脚本能查格式，查不了真假）。

## 1. 写作前准备

- [ ] 大纲已确认（[`02-大纲.md`](./02-大纲.md)）
- [ ] 素材库条目已准备好，编号记在 `article.md` 的 `materials` 字段
- [ ] 确定了本文主题（`theme` 字段），写作时按该主题的语气与结构

文章源文件是 `articles/<日期>-<slug>/article.md`，结构：

```markdown
---
title: 公众号排版，别再手调样式了
summary: 一句话摘要，发布到公众号摘要位，≤120 字
theme: default
template: tutorial
author: 某某
materials: [M2026110301, M2026110302]
cover: cover.png
publish_confirm: false
---

# 公众号排版，别再手调样式了

开头钩子……
```

> frontmatter 字段语义见 [`README.md` 第 8 节](./README.md#8-文章目录结构) 与脚本 `wechat_sop/frontmatter.py`。

## 2. 开头：前 3 段决定读者留不留

开头只有一个任务：**让读者觉得「这段跟我有关」**。可用套路（按文章类型选）：

| 套路 | 示范 | 适合 |
|---|---|---|
| 具体数据 | 「同一篇 2500 字的文章，我手调排版用了 32 分钟。」 | 观点/复盘 |
| 具体场景 | 「周三晚上 11 点，你还在调最后一段的行距。」 | 随笔/观点 |
| 痛点复述 | 「每次排版都要重新挑颜色、重新调间距。」 | 教程/盘点 |
| 反常识 | 「你以为排版是为了好看，其实是为了让人读完。」 | 观点 |

不要用的开头：「在这个信息爆炸的时代」「随着 XX 的不断发展」「作为一名 XX」。

## 3. 正文：一段一个意思

- 每段 1–3 句，只讲一个意思；超过 4 行就该拆。
- 小标题写**结论**而不是**话题**：
  - ❌「关于排版的一些思考」
  - ✅「排版慢，是因为每次都在重新做决策」
- 列表用于并列项；有先后顺序用有序列表，并写清步骤的前置条件。
- 数据必须有出处；没有出处的数字宁可删掉。
- **不得新增素材库之外的事实**：如果写着写着发现缺证据，回到素材库补，而不是「合理推测」。

## 4. 风格规范

### 4.1 中英文与标点

| 规则 | 示例 |
|---|---|
| 中英文、中文与数字之间加空格 | `用 Markdown 写，3 分钟完成` |
| 中文上下文用全角标点 | `，。！？：；（）` |
| 英文术语保持原样，不要强行翻译 | `frontmatter`、`inline style` |
| 加粗标点放在标记外 | `**重点**，而不是 **重点，**` |
| 不使用全角英文（`ＡＢＣ`）与半角中文（`，`）混用 | — |

这些规则由脚本 `check` 自动检查并可自动修复（见第 6 节）。

### 4.2 去 AI 腔清单

| AI 腔 | 改法 |
|---|---|
| 「综上所述」「总而言之」 | 直接给结论句 |
| 「不仅能…还能…」「不是…而是…」连用 | 拆成两句，说清具体差别 |
| 每段都用排比 | 保留一处排比即可 |
| 「希望对你有帮助」 | 换成具体行动：「把这篇文章存下来，下次排版前看一眼」 |
| 大量形容词堆叠（「高效、简洁、优雅」） | 换成可验证的事实（「3 分钟 vs 32 分钟」） |
| 万能句式「在当今社会」 | 换成具体时间地点人群 |

### 4.3 语言风格档案

本仓库支持把「我给谁写、怎么写」写进 `config/style.md`，成文与检查时作为参考：

```markdown
# 我的写作风格
- 读者：刚接手公众号的新媒体运营，不写 CSS
- 语气：像同事讲经验，不用感叹号堆情绪
- 从不写：「希望对你有帮助」「干货满满」
- 习惯：先给结论，再给证据，最后给行动
```

## 5. 结构检查

写完初稿后：

```bash
export PYTHONPATH=tools
python3 -m wechat_sop outline articles/2026-11-03-wechat-typography/article.md
python3 -m wechat_sop check articles/2026-11-03-wechat-typography/article.md --stage draft
```

`check --stage draft` 只跑内容类检查（标题/摘要/字数/占位符/标点/敏感词），不要求封面与排版产物，适合写稿阶段。

## 6. 格式自动修复

```bash
python3 -m wechat_sop format articles/2026-11-03-wechat-typography/article.md --write
```

`format` 命令做三件事，并默认跳过代码块、行内代码、URL、链接地址：

1. 中文上下文的半角标点 → 全角；
2. 中英文之间补空格；
3. `**重点，**` → `**重点**，`（加粗吞标点修正）。

运行后务必 `git diff` 看一遍：格式修复只应该改标点与空格，不应该改任何词。
