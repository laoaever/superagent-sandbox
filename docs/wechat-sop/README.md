# 公众号写作流程 SOP

> 版本：v1.0　｜　适用对象：本仓库的公众号内容创作者（个人或小团队）
> 配套脚本：`tools/wechat_sop/`（零三方依赖，Python 3.8+）
> 调研依据：[`00-research.md`](./00-research.md)

## 1. 目标与边界

**目标**：把「公众号写作」从个人手感变成可复用的流水线，让每一篇稿子都：
- 选题有依据（来自选题库/素材库，而不是拍脑袋）；
- 结构有模板（按文章类型选模板，不每篇重来）；
- 排版风格稳定（主题固定，不每篇调样式）；
- 发布前有清单（标题、字数、摘要、封面、图片、敏感词都有确定性检查）；
- **发布动作永远由人确认**。

**边界（重要）**：
- 脚本**不做自动发布**：不调 `draft/add`、不点群发、不做定时发布。
- 脚本只负责把内容准备到**「粘贴即可」**的状态：生成带「复制到公众号」按钮的预览页 + 合规 HTML 片段 + 发布前检查报告。
- 选题共创、大纲确认、成文定稿、配图选图、最终发布，**都有人工确认节点**（SOP 中标记为 👤）。

## 2. 全流程总览

```
 ①选题共创           ②大纲              ③成文              ④排版规范          ⑤配图规范           ⑥发布前检查          ⑦人工发布
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ topics   │──▶│ outline  │──▶│ draft.md │──▶│ render   │──▶│ images   │──▶│ check    │──▶│ 👤 粘贴发布 │
│ 选题库    │   │ 模板渲染  │   │ 写作规范  │   │ 内联 HTML │   │ 配图清单  │   │ 发布前清单 │   │ 人工确认    │
│ 👤 拍板   │   │ 👤 确认   │   │ 👤 定稿   │   │ 👤 预览   │   │ 👤 选图   │   │ 0 阻断项  │   │            │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

每一次流转都在**同一个文章目录**里完成（见第 8 节目录结构），任何一步都可以回退，产物都可 review。

## 4. 核心原则

### 4.1 一次只说一件事
一篇只讲一个主论点，其余内容服务于它。话题一多，读者记不住，标题也写不准。

### 4.2 先有素材再写稿
成文时**不得新增未经素材库登记的事实、数据、案例**（引用需标来源）。这是「不是 AI 编的」的底线。

### 4.3 结构先于文字
大纲没确认就写正文，通常等于写两遍。大纲必须写清：每一小节要论证什么、用什么证据。

### 4.4 排版是固定的，不是每次重新设计的
主题在仓库 `tools/wechat_sop/themes/*.json` 中定义，按文章类型选，不逐篇调参。详见第 5 节排版规范。

### 4.5 发布前清单可执行
检查项必须能落到 [`06-发布检查.md`](./06-发布检查.md) 的脚本检查里；不能自动化的项写成人工勾选项，不留「应该没问题」。

### 4.6 发布永远人工确认
脚本停在「粘贴即可」。预览页 → 点「复制到公众号」→ 公众号后台粘贴 → 人工检查 → 人工群发。

## 5. 排版规范摘要

完整版见 [04-排版.md](./04-排版.md)。默认参数（可直接被主题 JSON 覆盖）：

| 项目 | 规范 | 理由 |
|---|---|---|
| 正文字号 | 15–17px（默认 16px） | 手机正文宽约 345px，16px 每行 21 字左右，最舒适 |
| 行高 | ≥1.7（默认 1.75） | 低于 1.7 会明显拥挤 |
| 段间距 | 1.5em 左右 | 用段落留白代替缩进 |
| H1（文章内大标题） | ≤28px | 超过会占两三行 |
| H2 | ≤22px | 手机上新起一段 |
| 字号梯度 | H1 ≥ H2 ≥ H3 ≥ 正文 | 标题不得小于正文 |
| 强调色 | 全文唯一主色 | 颜色多了没有重点 |
| 图片宽度 | 100%，圆角，居中 | 与正文同宽，不悬浮 |
| 背景 | 纯色 / rgba 纯色，**不用渐变** | 渐变在深色模式会触发微信 `darkmode-no-gradient` 弹窗 |
| 外部链接 | 自动转脚注 | 公众号正文外部链接不可点击 |
| 中英文 | 之间加空格 | 观感 |
| 标点 | 中文上下文用全角 | 观感与规范 |

这些规则中可自动检查的部分，由 `python3 -m wechat_sop theme-lint` 与 `check` 命令强制执行。

## 6. 配图规范摘要

完整版见 [05-配图.md](./05-配图.md)。

- 每篇文章至少 1 张封面（16:9 或 2.35:1）+ 正文内 2–5 张配图。
- 配图在 Markdown 中用**相对路径**引用（`images/xx.png`），保证脚本能检查到文件是否存在、尺寸是否足够。
- 不要引用外链图片：公众号不接受外链，且脚本无法检查可用性。
- 每张图必须有 `alt`（说明这张图在说什么），并在图下方或正文里说明来源/版权。

## 7. 发布前检查清单摘要

完整版见 [06-发布检查.md](./06-发布检查.md)。`python3 -m wechat_sop check` 会输出阻断项（必须清零）与风险项（需人工确认）。

| 阻断项 | 规则 |
|---|---|
| 标题缺失 | frontmatter `title` 为空 |
| 标题超长 | > 30 字告警，> 64 字阻断（公众号 API 硬限） |
| 摘要缺失 | `summary` 为空，或 > 120 字 |
| 正文过短 | < 300 字（疑似未写完） |
| 正文过长 | > 6000 字（建议拆分） |
| 封面缺失 | 无 `cover` 或封面文件不存在 |
| 正文图片缺失 | `images/` 引用的文件不存在 |
| 正文图片过小 | 宽度 < 300px |
| 图片缺 alt | 配图没有说明 |
| 外部链接 | 正文存在无法保证点击的内部链接（自动转脚注处理） |
| 敏感词 | 命中 `config/checkwords.txt` 中的违禁/极限词 |
| 排版不合规 | `<style>`/`class`/`id`/`<div>`/`var()`/渐变等 |
| 半角标点、中英文粘连 | 中文上下文标点未全角、中英文之间无空格 |
| 未完成标记 | 正文仍有 `TODO`、`【待补】`、`{{占位}}` |
| 发布确认 | `publish_confirm` 未标记已确认（最后一道人工闸门） |

## 8. 文章目录结构

每篇文章一个目录，结构固定：

```
articles/2026-11-03-文章标题/
├── article.md        # frontmatter + 正文（Markdown），唯一可编辑源
├── outline.md        # 大纲（环节②产物，保留备查）
├── images/           # 正文配图（相对路径引用）
├── cover.png         # 封面（或 cover.jpg）
├── outline.html      # 可粘贴到公众号的 HTML 片段（脚本生成）
├── preview.html      # 带「复制到公众号」按钮的预览页（脚本生成）
└── check-report.md   # 发布前检查报告（脚本生成）
```

> 生成物（`outline.html`、`preview.html`、`check-report.md`）不建议手工修改，改 `article.md` 后重新运行脚本即可。

## 9. 脚本速查

所有命令在仓库根目录执行（`tools/` 需要加到 `PYTHONPATH`，或用下面的等价写法）：

```bash
export PYTHONPATH=tools

# ① 选题库
python3 -m wechat_sop topics list                    # 列出选题与状态
python3 -m wechat_sop topics add --title "标题" --angle "切入角度" --audience "人群"
python3 -m wechat_sop topics use T2026110301         # 选题立项，生成文章目录

# ② 大纲：模板 + 结构校验
python3 -m wechat_sop new --from-topic T2026110301 --template tutorial --slug my-article
python3 -m wechat_sop outline articles/my-article/article.md   # 输出大纲结构树 + 薄弱点

# ④ 排版：Markdown → 公众号 HTML 片段 + 预览页
python3 -m wechat_sop render articles/my-article/article.md --open
python3 -m wechat_sop theme-lint                     # 检查主题参数是否符合排版规范

# ⑥ 发布前检查
python3 -m wechat_sop check articles/my-article/article.md
```

各命令的详细说明见 [`README.md`](./README.md)。

## 10. 角色与周期建议

| 环节 | 谁做 | 建议耗时（3000 字文章） |
|---|---|---|
| ① 选题 | 主笔 + 运营 | 30 min（每周选题会） |
| ② 大纲 | 主笔 | 30–45 min |
| ③ 成文 | 主笔 | 2–4 h |
| ④ 排版 | 脚本 + 主笔预览 | 10 min |
| ⑤ 配图 | 主笔 / 设计 | 30 min |
| ⑥ 检查 | 脚本 + 主笔 | 10 min |
| ⑦ 发布 | 运营（人工） | 5 min |

> 小团队可以一人全包，但**每个环节的人工确认点不能省**：选题不确认会写偏，大纲不确认会返工，发布不确认会出事故。
