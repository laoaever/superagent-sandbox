## M2026110403 经验：AI 编程的三种典型失败模式
- 标签：经验/工程判断
- 来源：日常开发使用 AI 编程工具的观察整理（作者经验，非统计数据）
- 要点：①版本陈旧：生成结果依赖训练时见过的写法，容易给出过时 API 或已被替代的库；②凭空补全：缺失的前置条件（配置、依赖、鉴权）被默默补成看起来对的样子；③过度自信的说明：解释读起来通顺但没有对应到真实执行路径。共性：错误集中在「机械可写」之外，也就是边界条件、并发、权限、错误处理。
- 可引用：标为经验，不做比例结论；可引用具体例子描述，不引用数字

## M2026110405 调研：RAG 与 Agent 的常见实现形态
- 标签：调研/知识面
- 来源：公开技术文档与产品说明（向量检索、文件/工具调用型助手），2026-11
- 要点：RAG 的基本形态是检索 + 拼装上下文 + 生成；工程难点在切分、召回质量、引用与失效处理。Agent 的基本形态是模型在循环里选用工具、读取结果、继续下一步；难点在工具设计、终止条件、失败重试与权限边界。面试要的是取舍理由，不是名词定义。
- 可引用：可引用；讲机制不背书式定义

## M2026110406 经验：面试现场编程的评分其实看决定过程
- 标签：经验/面试观察
- 来源：面试与模拟面试的观察整理（作者经验，非统计数据）
- 要点：面试官通常同时在评三件事：需求理解（有没有先问清边界）、过程可见（思路是否被讲出来）、收尾意识（测试、异常、复杂度）。AI 工具能把「打字」这一段压缩，但不能替代这三件事；反过来，用 AI 却不解释选择，会让过程可见性直接掉到最低。
- 可引用：标为经验；不写具体公司、岗位与通过率
